## Scope — in this order

### 1. Export snapshot (server-truth)

`POST /api/export` takes JSON:

```
{ target, add[], remove[], prices: {TICKER: number | {CLASS: number}}, priceDate }
```

This is the same state the URL already encodes.

- Validate with Zod: at most 12 peers, prices > 0, price date not in the future.
- The server reloads cached fundamentals for target and peers, reruns screening, and recomputes the comps, stats and implied valuation with the **same domain functions** the browser uses.
- It **never trusts numbers sent from the browser**, only the inputs.
- The result is an `ExportSnapshot` (blueprint §11): app and methodology versions, `generatedAt`, target, peers, statuses, warnings, quotes, peer selection, summary.

**Unit test:** for the comps-golden fixture state (LII with CARR, AAON, TT, WSO and JCI at the documented test prices), the snapshot equals what the browser's `buildComps` produces from the same inputs, field by field.

### 2. Workbook builder (`src/export/workbook.ts`, `styles.ts`, `sanitize.ts`)

A pure function, `ExportSnapshot` → workbook, implementing blueprint §17 exactly.

#### Sheet 1: "Trading Comps"

- Header block in rows 1–6:
    - "PeerSet — Trading Comparables"
    - target name and ticker
    - SIC and its description
    - analysis date
    - "Prices as of <date> · source: entered by user"
    - "USD in millions, except per-share data"
- Headers in row 8; target in row 9 (bold, light fill); peers from row 11.
- Statistics block after a blank row: Mean, Median, High, Low, n, plus 25th and 75th percentile if the implied valuation is shown.
- **Columns:** Company · Ticker · Fin. through · Price · Equity value · EV · LTM revenue · LTM EBITDA · EBITDA margin · EV/Revenue · EV/EBITDA · P/E.
- **Statistics** are formulas over **peer rows only**: `AVERAGE`, `MEDIAN`, `MAX`, `MIN`, `COUNT`, `PERCENTILE.INC`. Excel skips text cells, so "NM" and "—" fall out automatically. Assert this in a test.
- **Implied valuation block**, when present on screen: 25th percentile / median / 75th percentile multiple × target metric → implied EV → implied equity value → implied price, all as formulas.
- **Footnotes:** the EBITDA definition, the NM policy, the basic-share note, active warnings, and the disclaimer.

#### Sheet 2: "Calculations"

One block per company:

- LTM bridge (FY + YTD − prior YTD = LTM) for revenue, operating income, D&A, net income and EPS
- EBITDA as a formula
- capitalization by share class (price × shares)
- every debt and cash face line, with an included/excluded flag and the reason
- not-in-EV items
- EV as a formula

Sheet 1's cells link here; links are shown in green.

#### Sheet 3: "Sources & Methodology"

- One row per fact used: company, metric, concept, period start and end, value in USD, form, accession, filed date, source (companyfacts or filing), and a `HYPERLINK` to the filing index.
- Then: definitions, the NM policy, limitations, the price source, app and methodology versions, and generation time.

#### Formatting

| Element | Format |
| --- | --- |
| USD millions | `#,##0.0_);(#,##0.0)` |
| Per share | `#,##0.00_);(#,##0.00)` |
| Multiples | `0.0"x"` |
| Percentages | `0.0%_);(0.0%)` |
| Dates | `yyyy-mm-dd` |
| NM, "—", Unsupported | Right-aligned grey text, never 0 |
| Fonts | Blue = hardcoded input; black = formula; green = link to another sheet |

- Freeze panes below the headers and after the Ticker column; set column widths; light banding on peer rows.
- Print setup: landscape, fit one page wide, repeat header rows.

#### Values

- Inputs are values stored in USD millions at full precision (divided by 1,000,000, never rounded); number formats do the rounding.
- Derived figures are formulas **with cached results** equal to the domain values, so any viewer shows the right numbers.
- Set full calculation on load.

#### Safety

- Every text cell is written as an explicit string.
- Text starting with `=`, `+`, `-`, `@`, tab or carriage return gets a leading apostrophe (`sanitize.ts`).
- Test it with a company name such as `=HYPERLINK(...)`.

### 3. Route and UI

- `/api/export` streams `PeerSet_<TICKER>_comps_<YYYY-MM-DD>.xlsx` with the correct content type. Use Node runtime, `maxDuration` 60. Check the file size: it must stay well under Vercel's 4.5 MB response limit.
- An **Export** button in the header:
    - disabled until at least one valid row exists;
    - shows "Exporting…";
    - user-safe errors.
- Exporting with missing or NM values is allowed. A note lists what's missing, as on screen.

### 4. Workbook validation (blueprint §16)

**Read-back tests** with ExcelJS:

- sheet names and header text
- numeric cells are numbers; NM and "—" are text, never 0
- every cached formula result equals the domain value for the comps-golden state, to the cent
- peers in the workbook equal the selected set
- unsupported companies never fall inside a statistics range
- stats equal the web table's stats
- freeze panes, number formats and hyperlinks as specified

**LibreOffice recalculation in CI:**

- Install `libreoffice-calc` in a CI job and convert the generated workbook headlessly so it recalculates.
- Read the values back and assert they match the cached values. This proves the formulas themselves are right, not only the cached numbers.
- Document the command in the decision note.

**e2e (fixture mode):**

1. LII, paste prices, click Export.
2. Playwright captures the download.
3. A test reads it with ExcelJS and checks three key cells: target EV/EBITDA, the median EV/EBITDA, and the implied price.

**Plugin review:** run the synced `audit-xls` and comps-analysis review skills on the generated comps-golden workbook. Fix or explain each finding in the report.
