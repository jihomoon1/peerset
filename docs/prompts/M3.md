## Scope — in this order

### 1. Home page and app shell

**Home (`/`):**

- One-line description and a ticker search box (validated client-side; Enter goes to `/c/<TICKER>`).
- Example links: LII, WSO, GGG, AAON.
- Three short bullets on how it works: SEC filings → LTM → your price → EV and multiples.
- The blueprint §1 disclaimer.

Keep the blueprint §6 visual system: dense, one accent, no hero imagery, no gradients.

**Shared footer:**

- Disclaimer.
- "Financial data: SEC EDGAR filings."
- "Prices: entered by you" (or Alpha Vantage attribution when that mode is on).
- GitHub link.
- App version and methodology version.

**`not-found` and `error` pages:** user-safe messages, never stack traces.

**Metadata:** title, description, and an Open Graph title and description. No image needed.

**Methodology link:** points to `docs/methodology.md` on GitHub for now. The in-app methodology page is M6.

### 2. End-to-end tests (fixture mode)

Add `@playwright/test` and `@axe-core/playwright` as dev dependencies.

**Fixture mode:** `PEERSET_SEC_FIXTURES=1` makes the server use the fixture-backed SEC client from the unit tests, so e2e never calls live SEC.

- The server must **refuse to start** in fixture mode when `VERCEL_ENV === "production"`.
- Test that refusal.

**Specs:**

1. Home → search "lii" → `/c/LII` → the operating table shows LTM revenue 5,302.2.
2. Open the EBITDA drawer → it shows the LTM bridge → Esc closes it and focus returns to the cell.
3. Enter price 500 with a date → EV/EBITDA shows 16.15x (or the app's display precision) → the EV drawer lists the debt lines.
4. WSO → two price inputs → P/E shows Unsupported with its reason.
5. An unknown ticker shows the error state.
6. **Keyboard only:** search, open a drawer, close it, enter a price.
7. **axe** on `/`, `/c/LII` (priced) and an open drawer: no serious or critical violations.

**CI:** an `e2e` job in `ci.yml`.

- `npx playwright install --with-deps chromium`
- Build, then start in fixture mode.
- Chromium only.
- Upload the Playwright report as an artifact when the job fails.

### 5. Production deploy (Jiho present; ask before each command)

**The Vercel project** (`peerset`, created in M0) has 0 deployments. Its first deployment goes to production; that's intended now.

**Environment variables:**

- Production: `SEC_USER_AGENT`. Jiho types the value — the same address she used before. Use `--sensitive`.

- Do **not** add `ALPHAVANTAGE_API_KEY` to Production.

**Connect the GitHub repo:** `npx vercel@latest git connect`. After this, merges to `main` deploy production and PRs get preview URLs. If the CLI can't do it, give Jiho the exact dashboard clicks.

**Deploy:** merging PR #7 (or whatever number it gets) deploys production through Git. Jiho merges. Then watch the deployment with `npx vercel@latest ls` / `inspect`.

**Domain:** confirm the production URL. Prefer `peerset.vercel.app`, which ADR 0002 says the project held in M0. Report the exact URL.

**Live checks**, from Jiho's machine, against production:

- `/`, then `/c/LII` (the operating table renders with live SEC data).
- `/api/fundamentals?ticker=LII`: 200 and `freshness` present. Call it twice and report both timings to show the cache works.
- `/c/WSO`, `/c/GGG`, `/c/AAON`, `/c/CARR`, `/c/TT`: report what renders for each.

- Check Vercel runtime logs for any 403 from SEC: `npx vercel@latest logs` or the dashboard.

**Deployment Protection:** production must be publicly reachable. Previews may stay behind Vercel Authentication.
