## Why "bring your own key", and the rules that keep it clean

**The licensing.** No free price provider allows public display of its data (blueprint §9). Alpha Vantage declined free educational access on 2026-10-28 (`docs/licensing.md`). Under BYO-key, **each visitor's browser calls Alpha Vantage directly with the visitor's own key.** That is the visitor's personal use of their own free key. PeerSet's servers never receive, store, cache or forward the key or the quotes.

**It works technically.** Planning checked on 2026-11-02: Alpha Vantage answers browser requests with `access-control-allow-origin: *`.

**Hard rules** (each one needs a test):

1. The key is never sent to any PeerSet route, log, analytics or error report. A Playwright network listener asserts that no request to PeerSet's origin contains the key.
2. Quotes are fetched only from `https://www.alphavantage.co`, only from the browser.
3. The server's `PRICE_PROVIDER` stays `user` in production. `/api/quotes` stays dev-only.
4. Filled prices are treated exactly like typed prices: they are user inputs.
    - They go into the URL state, so the user chooses whether to share a link.
    - The export recomputes from them as inputs (server-truth still applies to fundamentals).
5. Attribution wherever filled prices appear (as-of strip, workbook header): "Prices: Alpha Vantage, fetched with your key · close of <date>".

## Scope — in this order

### 1. Browser-side Alpha Vantage client (`src/prices/browserAlphaVantage.ts`)

- **Reuse:** the existing response parser and rate-limit/error detection from `src/prices/alphaVantage.ts`. Make the shared part isomorphic if needed.
- **Fetching:**
    - One request per symbol, sequential.
    - Paced to Alpha Vantage's documented free limit; default at least 1.2 s apart unless the docs say otherwise.
    - At most 13 symbols per click.
- **"Note" / "Information" payloads** (rate limit or daily cap, returned with HTTP 200):
    - Stop immediately.
    - Keep the prices already filled.
    - Show: "Alpha Vantage's daily limit was reached; filled X of Y. Enter the rest by hand or try tomorrow."
- **Cache:** per symbol and trading date in `localStorage` (wrapped in try/catch; works without storage), so reloading or re-clicking the same day spends no calls.
- **Share classes:** use the symbol mapping already chosen in M2b (e.g. WSO-B).

### 2. "Fill prices" UI on the workbench

- **A small "Price autofill" panel:**
    - key input (`type=password`)
    - "Remember on this device" checkbox (off by default; stores the key in `localStorage`)
    - "Forget key" button
    - a one-line explanation: "Your free key from alphavantage.co. It stays in your browser; PeerSet never sees it." Link to the support page for getting a key.
- **The "Fill prices" button:**
    - fills **empty** price inputs for the target and every loaded peer
    - "Overwrite existing prices" is an explicit option
    - shows per-row progress
    - sets the price date from each bar's date; if the dates differ, the existing earliest-date rule applies, and `W_PRICE_STALE` still works
- **Failure handling:**
    - an invalid key → a clear message
    - a symbol Alpha Vantage doesn't know → that row stays empty, with the reason
- **Accessibility:** labelled inputs, keyboard flow, a live region announcing progress.

### 3. Source labelling and export

- **Quote source:** add `"alpha_vantage_user_key"` (or your documented name) to the quote source type. The as-of strip, drawer and workbook show the attribution from rule 5.
- **Export:** `/api/export` accepts the source tag as an input. The workbook header and the Sources sheet say "Prices: Alpha Vantage via the user's own key, close of <date>; entered by the user's browser."
- **Licensing doc:** update `docs/licensing.md` with the BYO-key design, the hard rules above, and why it differs from server-side use.

### 4. SEC pacing fix (production finding from M6, part 6c)

**Finding:** On 2026-11-02 at 15:12:41–42 UTC, production sent SEC 10 requests per second (three peer loads plus an export), above ADR 0009's 8/s design cap.

**Fix:**

- **(a) Export reuses cache.** Exports skip SEC entirely for companies whose fundamentals are cached and whose submissions check is fresh. Pick a freshness window, e.g. 10 minutes, and document it.
- **(b) Lower per-instance pacing** so that one user's comps view plus an export stays at or below 8/s worst case. Write the arithmetic in ADR 0009, or in a new ADR that supersedes it.
- **(c) Two users at the same moment.** State honestly in the ADR what happens. A shared global limiter would need a datastore, which is out of scope: note it as future work.

**Test:** an export of an already-loaded comps set makes zero SEC requests (mocked client).

### 5. Lucid preferred-stock warning (README known limitation)

Methodology 0.4.3, warning only. **No value changes.**

**The gap:** preferred stock in temporary equity (e.g. "Redeemable convertible preferred stock", Lucid 2,906,257 thousand at 2026-06-30) is currently Unsupported and EV leaves it out **silently**.

**Rule:**

- When a face line in temporary equity looks like preferred stock or noncontrolling interest, EV gets the caution `W_NOT_IN_EV_UNCLASSIFIED`, naming the line and its value: "possible preferred stock not in EV: <label> <value>".
- This applies whether the line is classified or not.
- Recognize the standard temporary-equity concepts (e.g. `TemporaryEquityCarryingAmountAttributableToParent` and its children), so that the existing "material item not in EV" warning fires when they're recognized.

**Follow-through:**

- Update the LCID golden (warnings only) under the drift protocol: reason "definition change, methodology 0.4.3".
- Update `docs/reconciliation/LCID.md` and the README's limitations text.
